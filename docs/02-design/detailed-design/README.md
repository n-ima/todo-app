## spec-critic レビュー記録（2026-09-26）

| 指摘 | 内容 | 対応 |
|---|---|---|
| MAJOR M1 | 機材喪失後の新サーバーで Install が起動すると、空の DB のバックアップが世代を押し出し、新しい鍵で控えを上書きしうる | DD-10 §2 に復旧モード `-Recover`（控えの鍵を取り込み、起動しない）と、既存バックアップ検知時の確認を追加。§4 の機材喪失経路を変更 |
| MAJOR M2 | 再開モードが手順 6〜8 をまとめて飛ばし、管理者・鍵が作られない | 導入済みの判定を `install.completed` にし、各手順を成果物で個別判定（`has-admin`・`init-secrets` の 13） |
| MAJOR M3 | サービス登録前に `NT SERVICE\TodoApp` へ ACL を付与 | サービス登録（起動なし）を先にし、`sc.exe showsid` の SID で付与。実機確認を Install タスクの完了条件に |
| MAJOR M4 | E-LOCK-LOST の下書き保存が例外でロールバックされる／権限判定が先 | DD-01 §5 に結果型（コミット後に 409）を追加。DD-04 §4・DD-05 §3 でロック確認を権限判定より先に。結合テスト観点を明記 |
| MAJOR M5 | 更新前バックアップが成功として数えられ、再試行と警告を黙らせる | `backup_runs.kind`・`destination` を追加（DD-02）。再試行・警告・表示は `kind='daily'` だけで判定。`daily.lock` は DailyJob だけが取る（DD-09） |
| MAJOR M6 | 条件なし・「完了も表示」で描画量が無制限 | 全表示に 3,000 行の上限と段の縮退を追加。負荷試験データの形を定義（DD-06 §2・§3） |
| MINOR m1〜m15 | スライディング失効・文言の食い違い・opacity・モックの無効ボタン・移動先の整合・完全削除の順序・「他 n 件」の定義・完了状態の選択・ナビのクエリ引き継ぎ・復旧後の WAL・CLI の稼働中拒否と待ちタイムアウト・証明書更新手順・US-019 の置き換えの明記・E-CSRF と E-PROJECT-NAME・下書き復元時の無効値 | 全件反映（DD-01・DD-03〜DD-06・DD-10〜DD-12・README・screen-01-list.html） |
