# DD-06 一覧・絞り込み・期限の強調・カレンダー・CSV

## 1. 絞り込みクエリ（一覧・カレンダー・CSV・子の遅延取得で共通）

`TaskFilter` は URL のクエリで表す。一覧とカレンダーの切り替えリンクは同じクエリを引き継ぐ（US-012）。

| パラメータ | 値 | 意味 |
|---|---|---|
| `assignee` | 利用者 ID / `none` / 省略 | 担当者（`none` は未設定） |
| `status` | 状態 ID（複数可: `status=1&status=2`） | いずれかに一致 |
| `dueFrom` / `dueTo` | `yyyy-MM-dd` | 期限がこの範囲（両端を含む）。期限なしは除外 |
| `mine` | `1` | 自分が担当のタスクだけ（既定オフ） |
| `q` | 文字列（最大 100 文字） | タイトルの部分一致（§5） |
| `memo` | `1` | （Could）`q` をメモ本文にも適用 |
| `overdue` | `1` | 期限超過だけ（§6） |
| `done` | `1` | 完了扱いも表示（既定オフ） |
| `sort` | `due`（既定） / `manual` | 兄弟の並び順 |
| `view` / `date` | `month`（既定）/`week`、`yyyy-MM-dd` | カレンダーだけ |

不正な値は無視して既定値として扱う（400 にしない。ブックマークした URL が壊れても画面が開けるように）。

## 2. 一覧の組み立て（US-005・NFR-001）

```
TaskListService.Build(filter, user, today)
 1. rows = DD-02 §3 の一覧 SQL（有効なタスク全件・メモなし）。statuses・users を読む
 2. children[parentKey] を作る（parentKey = タスク ID、またはプロジェクト直下は "P{projectId}"）
 3. 一致 M = { t | Match(t) }。Match は §1 の全条件の AND。done ≠ 1 のときは完了扱いのタスクは一致しない
    ただし `status` に完了扱いの状態が含まれるときは、その条件の間 done = 1 とみなす（完了扱いの状態を選んだのに必ず 0 件になるのを防ぐ。画面の「完了も表示」もオンで表示する）
 4. 表示集合 V = M ∪ ancestors(M)。薄く表示する行 D = V \ M（完了の親・絞り込みの祖先。US-005・US-012）
 5. プロジェクト: 絞り込み条件が無いときは全プロジェクトを出す。条件があるときは V に配下を持つプロジェクトだけ
 6. 兄弟の並び: sort=due → (due_date 昇順・期限なしは末尾, sort_order, id)。sort=manual → (sort_order, id)
 7. 描画する行の決定（§3）
```

- 「絞り込み条件がある」とは `assignee`・`status`・`dueFrom`・`dueTo`・`mine`・`q`・`overdue` のいずれかが指定されていること（`done`・`sort` は含めない）。
- 0 件の表示: プロジェクトが 1 件も無い → 「タスクがありません」。条件があって M が空 → 「条件に合うタスクがありません」（US-005・US-012）。
- 性能: 15,000 行を 1 回で読み、メモリ上の辞書で組む（O(n)）。1 リクエストの目標はサーバー処理 200ms 以内（NFR-001 の 1 秒に対し描画と転送の余裕を残す）。
- 負荷試験のデータの形（テストフェーズで使う。A-006）: タスク 15,000 件・プロジェクト 30・利用者 30。段の分布は 1 段目 20%・2 段目 40%・3 段目 30%・4 段目以降 10%。完了扱い 60%。期限あり 80%（うち期限超過 5%）。メモ平均 2,000 文字。

## 3. 展開と遅延取得

- **段**: プロジェクト直下のタスクが 1 段目。
- 条件なし: 1〜3 段目の行を描画し、4 段目以降は描画しない。3 段目の行で V に子があるものは折りたたみボタン「▸」と子の件数を出す（US-005 の境界値: 3 段目は見え、4 段目は見えない）。
- 条件あり: V の全行を展開して描画する。ただし V が 500 行を超える場合は条件なしと同じ段の規則に切り替え、上部に「該当が多いため 4 段目以降は折りたたんでいます」と出す。
- **描画行数の上限（すべての表示に適用。NFR-001）**: 1 回の描画は最大 3,000 行。段の規則で描く行数が 3,000 を超える場合は、展開する段を 3 → 2 → 1 と減らして 3,000 以下になる最大の段までにし、上部に「件数が多いため {L} 段目までを表示しています。▸ で開けます」と出す（1 段目だけでも超える場合は 1 段目までを描く）。US-005 の「3 段目まで展開」はこの上限の範囲で守る（15,000 件の負荷試験のデータでは、完了を隠した既定表示は約 5,400 行になるため 2 段目までになる想定）。
- 折りたたまれた行の展開: `GET /api/tasks/{id}/children?<同じクエリ>` が直下の子（V に含まれるもの）の行 HTML（部分ビュー `_TaskRows`）を返し、`tree.js` が挿入する。返した子にさらに子があれば「▸」付き。一度取得した子は再取得せず、「▾」で隠す／表示するだけ。
- 描画済みの行の開閉（「▾」「▸」）はクライアント側だけで行う。開閉状態は保存しない。

## 4. 行の表示

| 列 | 内容 |
|---|---|
| タイトル | 詳細へのリンク（US-005。Q-11-3）。字下げで段を表す。D の行は文字色を `--text-dim` にし（`opacity` は使わない。design-tokens.md）、「（条件外）」または「（完了）」の小さな注記 |
| 状態 | 状態名のバッジ（完了扱いは中立色） |
| 担当者 | 表示名 / 「（無効）表示名」 / 未設定は「―」 |
| 期限 | `YYYY/MM/DD`。§6 の強調 |
| 優先度 | 高・中・低（高だけ強調色） |
| 操作 | 並び順が手動順のとき「上へ」「下へ」（`CanEdit` でなければ無効）、「＋子タスク」 |

プロジェクト行: プロジェクト名・「＋タスク」・（管理者に）名前変更と削除へのリンク。

## 5. キーワード検索（US-012）

- 検索語もタイトルも `NormalizeForSearch`（NFKC＋`ToLowerInvariant`）してから `Contains`（序数比較）。全角英数と半角、大文字と小文字は区別しない。ひらがなとカタカナは区別する（architecture.md §9）。
- 前後の空白を除いて空なら条件なし。
- （Could）`memo=1`: 一覧 SQL とは別に `SELECT id, memo FROM tasks WHERE deleted_at IS NULL` を読み、`NormalizeForSearch(memo).Contains(q)` の ID を M に加える（15,000 件×平均 2,000 文字で数十 ms。遅ければテストで計測して対策を実装タスクで決める）。

## 6. 期限の強調（US-013）

判定は `IClock.Today`（日本時間）で行い、完了扱いのタスクには付けない。

| 区分 | 条件 | 表示 |
|---|---|---|
| 期限超過 | `due_date < today` | 行の左端に赤帯、期限の日付を赤、アイコン「!」＋文字「期限超過」 |
| 期限間近 | `due_date = today` または `today + 1` | 黄色の印、アイコン「◷」＋文字「期限間近」 |
| なし | それ以外（明後日以降・期限なし） | 強調なし |

- 一覧の先頭の「期限超過 n 件」: 絞り込みに関係なく、有効な全タスク（ゴミ箱・削除済みプロジェクト・完了扱いを除く）で数える（architecture.md §9）。0 件なら「期限超過 0 件」を中立色で出す。クリックで `/?overdue=1`（他の条件を外す）。
- 詳細画面・カレンダーでも同じ判定と表示（同じ部分ビュー `_DueBadge` を使う）。

## 7. カレンダー（US-014・FR-006）

- `GET /calendar?view=month|week&date=yyyy-MM-dd&<§1 の条件>`。`date` 省略時は今日。週は日曜始まり（月表示も日曜始まりの 6 週グリッド）。
- 対象: M のうち期限のあるタスク（D の祖先は出さない）。開始日があれば開始日〜期限の帯、無ければ期限日の点（US-014）。期限が無いタスクは出さない。表示期間と重なるものだけ。
- 開始日だけあって期限が無いタスクは出さない（期限なしと同じ扱い）。
- 帯の配置: 週（行）ごとに、開始の早い順・期間の長い順に空いている最小の段へ置く（貪欲法）。帯は週の境目で分割する（次の週の行では「（続き）」として左端から描く）。月表示は段 0〜2（`Calendar:MonthMaxPerDay`=3）だけを描き、段 3 以降に置かれた帯・点は描かない。各日のセルに「他 n 件」を出す。**n ＝ その日にかかるタスクのうち、そのセルに描かれなかった件数**（1 件以上のときだけ表示）。「他 n 件」を押すとその日のタスク一覧をダイアログで出す（各行は詳細へのリンク）。週表示は全件を描く。
- 移動: 「前月」「次月」（週表示は「前週」「次週」）と「今日」。クエリの条件は保つ。
- 帯・点のクリックで詳細へ遷移。期限超過・期限間近は §6 と同じ色＋文字（帯の先頭に「期限超過」等のラベル）。
- 書き込み操作（ドラッグ・作成・日付変更）は置かない（FR-006）。日表示は作らない。

## 8. CSV 書き出し（US-018）

- `GET /export.csv?<§1 の条件>`（ログイン済みのみ。NFR-006 (5)）。
- 行: M（D の祖先は含めない）を一覧と同じ木の順（前順）で出す。展開状態には依存しない。
- 列: `プロジェクト,親タスク,タイトル,状態,担当者,開始日,期限,優先度`（（Could）`memo=1` のとき `メモ` を末尾に追加）。親タスクは直上のタスクのタイトル（プロジェクト直下なら空）。日付は `YYYY/MM/DD`、優先度は高/中/低、担当者は「（無効）」付き。
- 形式: UTF-8（BOM 付き）、改行 CRLF、RFC 4180（`,` `"` CR LF を含むフィールドは `"` で囲み、`"` は `""`）。
- CSV インジェクション対策: 文字列フィールドの先頭が `=` `+` `-` `@` タブ CR のとき、先頭に `'` を付けてから上記のエスケープをする（全文字列列に適用）。
- ファイル名: `tasks-YYYYMMDD-HHmm.csv`（日本時間）。`Content-Disposition: attachment`。

## 9. （Could）ドラッグ＆ドロップ（US-021）

後から足す場合の形だけ定める: 一覧のドラッグは `POST /tasks/{id}/move` をそのまま使う。カレンダーの日付ずらしは `POST /api/tasks/{id}/shift-dates`（本文 `days`）を新設し、`CanEdit`・他人の有効なロックがあれば `E-LOCK-HELD`・FR-002 の検証を行い、開始日と期限を同じ日数ずらす。導入時は FR-006 の記述を変更する（再ゲート）。
