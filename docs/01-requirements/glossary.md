# 用語集

画面の文言と文書はこの用語に統一する（Q-08-1）。

| 用語 | 定義 | 備考 |
|---|---|---|
| TODO アプリ | このアプリの呼び名 | アプリ名の中だけ「TODO」を使う。個々の仕事は「タスク」と呼ぶ（Q-08-1） |
| プロジェクト | 階層の最上位のまとまり。タスクを持つが、自身は担当者・期限・状態を持たない | 作成・名前変更・削除は管理者だけ（A-001）。「案件」とは呼ばない |
| タスク | 1 件の仕事。タイトル・状態・担当者・開始日・期限・優先度・メモを持つ | 「TODO」「課題」とは呼ばない（Q-08-1） |
| 親タスク / 子タスク | あるタスクの直下にあるタスクを子タスク、その上を親タスクと呼ぶ。入れ子の段数に上限は無い | 親の状態・期限は子から自動計算しない（Q-03-2） |
| 階層 | プロジェクト > タスク > 子タスク > … の木構造。段はプロジェクトの直下のタスクを 1 段目として数える | 一覧では既定で 3 段目まで展開する（Q-03-1・US-005） |
| 担当者 | タスクを受け持つ利用者。0 人または 1 人 | 担当者と管理者だけがそのタスクを編集できる（Q-03-27） |
| 開始日 / 期限 | タスクを始める日 / 終えるべき日。どちらも任意。日単位（時刻は持たない） | カレンダーでは開始日〜期限を帯で表示する（Q-03-5） |
| 優先度 | 高・中・低の 3 段階。既定は中 | Q-03-3 |
| 状態 | タスクがどこまで進んだかを表す値。管理者が定義した選択肢から選ぶ | 初期値は「未着手」「進行中」「完了」（US-015） |
| ワークフロー | 状態の並び（選択肢とその表示順）の定義。アプリ全体で 1 つ | 承認フローや自動化ルールの意味ではない（Q-03-12）。遷移の順序制約も持たない（Q-03-14） |
| 完了扱い | 状態に付ける印。この印の付いた状態のタスクは「完了したタスク」として扱う | 完了の非表示・期限超過の判定・親の完了警告に使う。1 つ以上必要（US-015） |
| メモ | タスク 1 件につき 1 つある、Markdown 記法で書く自由記述欄 | 独立したページは作らない（Q-03-11）。コメント欄とは別物で、コメント欄は作らない（Q-11-2） |
| プレビュー | Markdown で書いたメモを整形して表示したもの | HTML・スクリプトは実行しない（NFR-007） |
| ロック（編集ロック） | タスク 1 件（そのメモを含む）を 1 人だけが編集できるようにする排他の仕組み | 「編集する」で取得し、「保存」「キャンセル」で解放する（Q-03-17・Q-03-18） |
| 自動解放 | 最後の操作から 30 分操作が無いとき、システムがロックを解放すること | 編集中の内容は下書きとして残る（Q-03-18） |
| 強制解除 | 管理者が他人のロックを解放すること | 変更履歴に残る（Q-03-20） |
| 下書き | 自動解放・強制解除・保存失敗のときに残る、本人だけが見られる未保存の編集内容 | 次に編集を始めるときに復元か破棄かを選ぶ（US-010） |
| ゴミ箱 | 削除したタスクが 30 日間置かれる場所。この間は元に戻せる | 30 日を過ぎると完全削除される（Q-03-23） |
| 完全削除 | データベースからタスクを消し、ゴミ箱からも戻せなくすること | ゴミ箱に入って 30 日を過ぎたときだけ行う（FR-004） |
| 変更履歴 | タスクの状態変更・担当変更・ロック強制解除の記録（日時・操作者・変更前・変更後） | それ以外の項目の変更は記録しない（Q-03-24） |
| 通知 | アプリの画面内の通知一覧に届くお知らせ。担当割り当てと期限（前日・当日）の 2 種類 | メール・チャットには送らない（Q-03-15・Q-03-16） |
| 期限超過 | 期限が今日より前で、完了扱いでない状態のタスク | 赤で表示する（Q-11-5） |
| 期限間近 | 期限が今日または明日で、完了扱いでない状態のタスク | 黄色の印を付ける（Q-11-5） |
| 管理者 | 利用者管理・ワークフロー定義・ロック強制解除・プロジェクト管理・全タスクの編集ができる利用者 | 最低 1 人必要（US-003） |
| 一般利用者 | 全タスクを閲覧でき、タスクを新規作成でき、自分が担当のタスクと担当者が未設定のタスクを編集できる利用者。他人のタスクを付け直すリーダー役は管理者ロールで使う（Q-03-32） | Q-02-2・Q-03-27・Q-03-31・A-002 |
| サーバー運用者 | 社内サーバー上でセットアップ・更新・復旧のスクリプトを実行し、証明書やホスト名を設定する人。アプリのロール（管理者）とは別の概念で、多くの場合同じ人が兼ねる | requirements.md §5.0・§5.10 |
| 利用者 | このアプリにログインして使う人の総称（管理者と一般利用者） | environment.md の「ユーザー」は、このプロジェクトの発注者（要件を決めてリリースの人手作業を行う人）を指す |
| 初期パスワード | 管理者が利用者の登録時や再設定時に決めて本人に渡すパスワード。初回ログイン時に変更が強制される | US-002・US-003 |
| 手動順 | 一覧の並び順の 1 つ。同じ親の中で「上へ」「下へ」で決めた順に並べる。既定の並び順は期限の昇順 | US-007・US-012・A-004 |
| 未読 / 既読 | 通知の状態。クリックすると既読になる。未読の件数はヘッダーに表示する | US-016 |
| 自動保存 | ロック中の編集内容を、保存とは別にサーバーへ定期的に送ること。他の人には見えず、下書きの元になる | US-010 |
| 最終更新日時 | タスクの項目またはメモが最後に保存された日時。システムが自動で記録する | US-004・§4 成功指標 3 |
| 無効化 | 退職などで利用者をログインできなくすること。利用者とそのタスクは消えない | US-003 |
| セットアップスクリプト | 社内サーバーへの初回導入（データベース初期化・管理者作成・Windows のサービス登録（自動起動））を 1 コマンドで行うスクリプト | Q-10-1・US-019 |
| 更新スクリプト | 停止 → バックアップ → 入れ替え → スキーマ変更（承認制） → 起動を 1 コマンドで行うスクリプト | Q-10-2・US-022 |
| バックアップ | データベースを暗号化して社内の別サーバーの共有フォルダへ毎日保存したもの。7 世代残す | Q-10-3〜Q-10-6 |
| 復旧（リストア） | バックアップの世代を選び、現在のデータをその時点の内容で置き換えること | 復旧スクリプトで行う（Q-10-4・US-020） |
| スキーマ変更（マイグレーション） | 新しい版に合わせてデータベースの構造を変えること | SQL を提示し承認を得てから適用する（Q-09-9） |
| 日次処理 | 1 日 1 回動く処理（バックアップ・ゴミ箱の完全削除・期限の通知・古いログの削除）。サーバーが日中だけ動くため、その日最初のアプリ起動時、または起動中の日付変更時に実行する | US-019・Q-09-14 |
