# 変更請求台帳

運用中（全フェーズ done）のプロジェクトに対する変更依頼の記録。**1依頼 = 1CR = 1行**。
処理手順は `change-request` スキル（`.github/skills/change-request/SKILL.md`）が正。
ここに残らない変更は、次のセッションにも振り返りにも存在しないのと同じになる。

| CR | 受付日 | 依頼（1行） | 分類 | 影響範囲 | 状態 | 記録 |
|---|---|---|---|---|---|---|
| | | | | | | |

- **分類**: 1=軽微 / 2=要件・設計変更 / 3=バグ修正（設計変更なし） / 4=緊急ホットフィックス
  （AGENTS.md「差分駆動の原則」の4分類+例外条項（小規模ファストパス））
- **影響範囲**: 辿った要求ID・タスクID・テストケースID（例: `US-003 / TASK-012 / UT-021`。ID 体系は `docs/00-overview/README.md`）。
  分類1は「なし」と明示する
- **状態**: `受付` / `対応中` / `完了` / `見送り`（見送りの理由は「記録」欄に書く）
- **記録**: 関連する ADR・「実装乖離あり」注記・learnings 追記など、CR が残した痕跡への参照

運用ルール:

- 新しい CR は表の末尾に追加する。番号は `CR-001` からの連番（欠番を再利用しない）。
- 1つの CR に複数の依頼を詰め込まない（影響範囲が追えなくなる。分けて採番する）。
- リリースのゲート承認時、完了した版のサイクル分の行を
  `docs/00-overview/archive/change-requests-v<版>.md` へ退避する
  （progress.md の申し送りと同じ肥大化対策。進行中・見送りの行は本文に残す）。
