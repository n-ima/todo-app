# PROPOSALS.md — 提案トレーサビリティ台帳

監査・振り返り・外部レビューで出た改善提案を1行1件で登録し、採否と対応先を追跡する台帳。

運用規則:

- 監査・振り返り（/10-retrospective・外部監査）の提案は**必ずここに登録する**
  （採否未定でも open で登録。登録漏れは「提案の無音消失」であり監査指摘の対象）。
- 状態の更新は **/90-apply-retrospective が行う**（適用したら applied + D番号、
  見送り・不採用は deferred / rejected + 理由）。
- 詳細な議論・根拠は対応する D 記録（`DECISIONS.md`）と出典の監査ファイルが正。
  本台帳は索引に徹する。
- **採番規則（2026-09-10 改定・再監査 2026-09-09 OP-1）**: 1 監査＝1 接頭辞。接頭辞は出典ファイル名から機械的に決める（監査回数に依存しない）。`external-reaudit-2026-09-09` → `A6-`、`external-reaudit-2026-08-31`（未登録分の遡及）→ `A7-<原ID>`（例 A7-H-4。§6 の無番号 MEDIUM 群は `A7-M-1..9` に本台帳で付番）、`independent-harness-audit-2026-08-31-codex` → 監査ファイル自身の ID `IA-20260831-NN` / `R-NN` をそのまま使う。
- **宣言と突合**: 各監査 md の先頭行に `<!-- proposals: A6-1..24, A7-H-1..11, IA-20260831-01..15, R-01..09 -->` の形で起票 ID を宣言する（カンマ区切り。`X..N` は X 末尾の数字から N までの範囲展開、ゼロ埋め幅は X に従う）。`python tools/validate-harness.py` が宣言 ID 集合 ⊆ 本台帳の ID 集合を検査する（既定 WARN。`--ledger-strict` で ERROR。CI は台帳登録完了後に `--ledger-strict` へ切替＝2026-09-10 統合で切替済み）。宣言の無い監査 md は対象外（過去監査は遡及登録の対象外）。
- **applied の 3 点**: applied と記録できるのは (1) D 番号、(2) 検証コマンドと実行結果、(3) **CI 緑の run URL** の 3 点が理由欄に揃ったときだけ。CI が赤の間はどれだけローカルで通っても applied にしない（再監査 2026-08-31 C-2・2026-09-09 RG-2）。
- **登録日 / 状態更新日（2026-09-10 追加・再監査 2026-09-09 OP-4）**: 登録日は本台帳に行を登録した日、状態更新日は状態列を最後に変えた日（YYYY-MM-DD）。初期値は機械補完＝登録日は出典の日付（2026-09-10 の統合で一括登録した A6-/A7-/IA-/R-/子 ID の行は 2026-09-10）、状態更新日は `git blame` の行最終変更日。以後は /90-apply-retrospective が状態を変えるたびに状態更新日を書き換える。`python tools/effort-report.py --kpi` が未適用（open/partial）の最古滞留日数と監査→適用（登録日→状態更新日）の中央リードタイムを出し、`python tools/validate-harness.py` (e) が列の存在・日付形式・順序（状態更新日 ≥ 登録日）を検査する。
- **partial（新設）**: applied と記録したが機械ゲートとしては未完成のもの（再監査 2026-09-09 RG-13 で A2-4/A3-4/A3-5 を差し戻し）、および本波で実装済みだが CI 緑 run URL が未記入のもの。残作業は子 ID（例 `A3-4b`）で起票し、親行は partial のまま子が applied になった時点で applied に戻す。
