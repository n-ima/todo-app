# タスク: todo-cli（CLI TODO ツール）

D049 の E2E 通し実行で使った課題と同一の、意図的に小さく決定論的に検証できる
グリーンフィールド課題。`tools/e2e-run.py` がこのファイルを読み、
`memo` を両アームの `requirements/memo.md` に配置し、
`scripted-replies` / `scripted-replies-bare` を順に投入する。
成否判定は同ディレクトリの `check.py`（決定論チェッカー）が行う。

## memo（両アーム共通の入力）

```memo
# 要件メモ

コマンドラインで動く個人用 TODO 管理ツールが欲しい。

- Python 標準ライブラリだけで動く、1ファイルのスクリプト `todo.py` にしてほしい
- 使い方（この4コマンドは名前も含めてこのとおりにする）:
  - `python todo.py add "タスク名"`  … タスクを追加。追加した順に 1 からの連番が付く
  - `python todo.py list`            … 全タスクを番号付きで一覧表示。完了したタスクは
                                       `[x]` のような印付きで、未完了と見分けられること
  - `python todo.py done <番号>`     … 指定番号のタスクを完了にする（削除はしない）
  - `python todo.py delete <番号>`   … 指定番号のタスクを削除する
- データはユーザーのホームディレクトリ配下の1ファイル（JSON など形式は任意）に保存し、
  PC を再起動しても消えないこと
- 使うのは自分ひとり。共有・同期・GUI・Web・ログイン機能は不要
- Windows / macOS / Linux のどれでも動くこと
- unittest か pytest のテストを付けて、全部通しておくこと
```

## 受入条件（check.py がコード化している内容）

チェッカーは生成物ディレクトリから `todo.py` を探し、一時ディレクトリに
差し替えた USERPROFILE / HOME 環境で実際にコマンドを実行して検証する:

1. `add` を2回実行してどちらも終了コード 0
2. `list` に追加した2タイトルが表示される
3. `done 1` の後の `list` で、1番目のタスクの表示行が完了の印付きに変わる
4. `delete 2` の後の `list` から、2番目のタイトルが消える（1番目は残る）
5. テストファイル（`test_*.py` / `*_test.py`）が存在し、テストスイートが全件成功する

補助観測（合否に含めない）: データがホーム配下に保存されたか（環境差し替えで検出）。

## scripted-replies（harness アーム）

D049 の実走行と同じ発話系列。`---` の行が発話の区切り。
ゲート承認・自動継続・再開（「続きをお願いします」）は D049 で実測済みの文言を使う。

`# expect: <条件>` はその発話を送る**前に**満たされているべき GATE_STATUS の到達状態
（装置 v2・EV-8。`#` 行はコメントなので発話本文には入らない）。未達なら装置が督促
（`kind=nudge`、上限は `--max-nudges`）を送って再確認し、なお未達でも台本は続行する
（verdict は check.py が決める。督促は結果 JSON の `calls[]`/`state_trace[]` に残り、
bare アームには同数の継続発話が与えられる）。条件はライトパス（承認①で要件+設計が
一括 done）とフルパスの両方で成り立つ「到達状態のみ」を書く。

```scripted-replies
/00-start-project
---
# expect: exists=true
全部仮置き案どおりでOKです。そのまま進めてください。
---
# expect: requirements=in_progress|pending_approval|done
要件を承認します。ゲートを通過して次のフェーズへ進んでください。
---
設計はすべて提案どおりでOKです。確定してください。
---
設計を承認します。次のフェーズへ進んでください。
---
# expect: requirements=done, design=done
/05-implementation-plan
---
実装計画を承認します。/06 で実装を開始してください。
---
# expect: implementation=in_progress|done
/06-implement-task
---
続きをお願いします。
---
続きをお願いします。テスト・リリースまで進めてください。タグ付けなど人手が必要な操作はコマンド提示だけで構いません。完了したら状況を報告してください。
```
